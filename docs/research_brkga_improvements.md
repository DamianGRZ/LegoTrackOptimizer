# BRKGA Research: Improvements for LEGO Track Optimizer

## Thesis Goal

The goal of this work is to develop and investigate combinatorial optimization methods for the problem of automatically designing closed layouts composed of discrete modular elements. The problem involves arranging a finite set of elements with defined geometry and connection rules such that the resulting structure satisfies the closure condition (no loose ends), maximizes the utilization of available elements, and accounts for simplified physical constraints arising from connection geometry. The application domain is the Lego City Trains railway track system, which serves as a representative example of the problem of designing closed layouts from discrete modular elements.

As part of the work, the student will formalize the problem, including the definition of the solution space, constraints, and objective function. Then, they will propose an appropriate solution representation and design dedicated search operators tailored to the problem's specifics. The properties of the proposed approach will be investigated, including the influence of algorithm parameters on solution quality, convergence of the optimization process, and scalability of the method depending on the number and variety of available elements.

The expected result is a working implementation of the proposed method along with experimental analysis confirming its effectiveness. The obtained layouts will undergo physical verification using a set of tracks and a Lego City Trains train, which will allow for assessing the practical correctness of solutions generated by the algorithm.

## Detailed Analysis

### 1. Elite-Only Local Search (Piece Insertion) — Priority 9/10

**Paper reference**: Section 4 (hybridization). Local search on elite solutions after each generation is the most common BRKGA hybrid (present in ~35% of studies). The canonical pattern: decode elite -> apply problem-specific local search -> re-encode back to RK space.

**Current gap**: The existing `TrackRepairPipeline` runs on ALL offspring including mutants and random individuals. The paper recommends applying expensive repair/improvement only to elites since these have highest probability of producing useful offspring.

**Proposed approach**: A LEGO-specific local search that:
1. Takes an elite chromosome that decodes to a closed loop using N pieces
2. Tries adding one additional piece to each position in the sequence
3. Checks if the result still closes
4. If yes, updates the chromosome

This "piece insertion local search" directly improves the main optimization difficulty: finding layouts that close AND use many pieces simultaneously. The decoder's greedy port-priority construction cannot backtrack, so it frequently terminates a working loop earlier than necessary.

**Implementation**: New `Callback` that every 10 generations takes the top-5 elites, decodes them, runs closure-preserving piece insertion, and re-encodes via a new `re_encode_layout()` function in `encoding.py`.

**Expected benefit**: Significant improvement in best solution piece count. Each local search pass can typically add 1-3 pieces to an already-feasible layout.

### 2. Shake Operator on Elites — Priority 8/10

**Paper reference**: Section 5.3. Shake perturbs elite chromosomes (redraw a subset of genes with small random noise) while fully re-randomizing all non-elites. This is distinct from the reset operator in that it disturbs the elite itself.

**Current gap**: The `StagnationCallback` only replaces worst non-elites, leaving elites untouched. A locally-optimal elite (e.g., a perfect circle using 16 curves out of 40 available) will keep dominating through biased crossover indefinitely.

**Proposed approach**: Two types of shake for this problem:
- **Gene-level shake**: Replace random subset of elite genes with new uniform random values
- **Route-level shake** (problem-specific): Perturb only branch slot genes (200-216) while keeping main loop genes (0-100) stable. This encourages switch topology changes without destroying working closed loops.

**Implementation**: Extend `StagnationCallback` with an elite perturbation phase that adds Gaussian noise to branch slot genes when `_gens_without_improvement == patience`.

**Expected benefit**: Escaping sub-optimal fixed-point cycles. Particularly valuable for switch-containing configurations where the optimizer settles for switch-free circles.

---

### 3. Flat Fitness Landscape Fix — Priority 8/10

**Paper reference**: Section 6. BRKGA performs poorly when the fitness landscape is flat. The paper identifies highly constrained problems with low initial feasibility as the primary cause and recommends auxiliary objectives that reward partial feasibility.

**Current gap**: When the decoder produces an empty layout (n_pieces=0, common in early generations), the objective is flat: `F=[0.0]` for all such solutions. This creates a degenerate elite subset of identically-valued chromosomes.

**Proposed approach**: Add a secondary "partial closure" metric when n_pieces=0. Instead of returning flat F=0.0, compute fitness from the maximum angular closure achieved before the decoder terminated. For example, a chromosome that built 12 pieces accumulating 270 degrees of angle before terminating is "closer" to feasibility than one that built 4 pieces accumulating 90 degrees.

**Implementation**: Expose partial angle from the decoder's return value. In `_evaluate`, when `layout.n_pieces == 0`, use normalized partial angle as objective: `F = [-partial_angle / 360.0]`.

**Expected benefit**: Significantly faster first feasible solutions in early generations (the main bottleneck for complex configs like with_switches.yaml).

---

### 4. Island Model — Priority 7/10

**Paper reference**: Section 5.1. The most common BRKGA extension in the reviewed literature. Multiple populations evolve independently, periodically exchanging best elites. Prevents genetic drift and premature convergence.

**How it maps**: The LEGO layout problem has inherent multiple basins of attraction: circles, ovals, racetracks, and switch-containing layouts are structurally distinct topology classes. A single population tends to converge on the simplest basin. Islands initialized with different heuristic seeds would maintain pressure across topological classes.

**Proposed approach**: 2-3 islands, each seeded differently:
- Island 1: Circle/oval seeds (simple closure)
- Island 2: Racetrack seeds (larger layouts)
- Island 3: Switch-containing seeds (complex topology)

Every 50 generations, exchange top-5 elites between islands.

**Implementation**: Requires orchestrating multiple pymoo `minimize` calls or a custom outer loop. Not natively supported by pymoo's BRKGA.

**Expected benefit**: Prevents pathological convergence to simple circles. Pushes solutions toward 60-80%+ utilization more consistently.

---

### 5. Structured Fresh Injection — Priority 7/10

**Paper reference**: Section 5.2. Reset individuals should ideally be sampled from the same distribution as the initial population, not pure uniform random.

**Current gap**: `StagnationCallback._inject_random` generates uniformly random chromosomes in [0,1]. These are almost always infeasible and add no useful search pressure.

**Proposed fix**: Replace `np.random.uniform(xl, xu)` with `MultiSegmentSampling._closure_aware_chromosome()` calls to inject structured feasible-pattern chromosomes.

**Implementation complexity**: Low (5-line change in `problem.py`).

**Expected benefit**: Better stagnation recovery quality. Fresh individuals contribute meaningful genetic material instead of pure noise.

---

### 6. Implicit Path-Relinking (IPR) — Priority 6/10

**Paper reference**: Section 5.6. IPR works entirely in [0,1]^n space. Given two elite chromosomes x1 and x2, generates intermediates: x(t) = x1 + t*(x2 - x1) for t in {0.1, 0.2, ..., 0.9}. Each is evaluated and the best is retained.

**How it maps**: RK encoding makes IPR semantically meaningful. Interpolating between two elite layouts explores the "path" between different good configurations in chromosome space. E.g., interpolating between a working 30-piece oval and a 28-piece racetrack might discover a 32-piece hybrid.

**Implementation**: New `Callback` activating in final 20% of generations. Takes top-10 elite pairs, evaluates IPR intermediates (9 evaluations per pair).

**Expected benefit**: Moderate improvement in final solution quality for polishing phase.

---

### 7. Adaptive Bias Schedule — Priority 5/10

**Paper reference**: Section 5.4. The bias parameter rho controls elite gene dominance in offspring. Adaptive schedule:
- Phase 1 (early): High bias (0.80-0.85) to exploit heuristic seeds
- Phase 2 (middle): Standard bias (0.70)
- Phase 3 (late): Lower bias (0.60-0.65) to diversify near convergence

**Implementation**: New `Callback` modifying `algorithm.mating.crossover.bias` each generation. Requires inspecting pymoo's internal crossover parameter structure.

**Expected benefit**: Better search phase alignment. Particularly valuable for thesis parameter sensitivity experiments.

---

### 8. Decoder 1-Step Lookahead — Priority 5/10

**Paper reference**: Section 4 (matheuristics). Integrating optimization into the decoder itself.

**Proposed approach**: At each construction step, evaluate whether the candidate piece selection still allows future closure (check if remaining angular budget can be achieved with remaining inventory). Skip piece selections that make closure impossible.

**Implementation complexity**: High. Requires modifying the core decoder loop with angular budget tracking.

**Expected benefit**: Converts some non-closing layouts to closing ones without changing the GA layer.

---

### 9. Multi-Parent Crossover — Priority 3/10

**Paper reference**: Section 5.5. Uses pi_e elite + (pi_t - pi_e) non-elite parents per offspring.

**Assessment**: pymoo's BRKGA does not expose multi-parent crossover. Would require forking the BRKGA class. Benefit is uncertain compared to simpler improvements.

## Key Paper Observations for This Problem

### Why BRKGA fits better than NSGA-II:
- Problem is now single-objective + constraints (NSGA-II designed for multi-objective Pareto)
- RK encoding eliminates need for custom crossover/mutation operators
- Construction decoder maps smoothly from [0,1]^n to solutions
- Double elitism provides fast convergence with structured elite preservation

### Known BRKGA risks and mitigations:
- **Premature convergence**: Mitigated by epsilon-decay + stagnation detection (existing) + shake operator (proposed)
- **Flat landscapes**: Mitigated by partial closure reward (proposed)
- **Diversity loss**: Mitigated by island model (proposed) + structured injection (proposed)

### Paper's position on multi-objective BRKGA:
- Multi-objective BRKGA (mp-BRKGA) exists but is scarce in literature
- Only applied to bi-objective problems so far
- Not recommended unless multiple conflicting objectives are essential
- Current single-objective + constraints approach is the standard BRKGA pattern
