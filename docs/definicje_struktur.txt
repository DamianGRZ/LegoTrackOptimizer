DEFINICJE STRUKTUR DANYCH
=========================


REPREZENTACJA KLOCKA (TrackPiece)
---------------------------------
Lokalizacja: src/data.py:41-78

Pola:
  id: str                          np. "R40_LEFT", "STRAIGHT_16"
  name: str                        czytelna nazwa klocka
  piece_type: str                  "straight", "curve", "switch", "crossing", "bumper"
  index: int                       zakres 0-9, numer używany w chromosomie
  fk: FKDeltas                     transformacja geometryczna
  ports: Tuple[Port, ...]          lista punktów połączeń
  length: float                    długość prostych (studs)
  radius: float                    promień łuku (studs)
  angle: float                     kąt łuku (stopnie)
  direction: str                   kierunek ("left"/"right" dla łuków)
  radius_mm: float                 promień w mm (dla fizyki)
  speed_limit_ms: float            limit prędkości (m/s)
  is_terminator: bool              czy kończy tor (bumper)
  routes_data: Optional[List]      surowe dane tras z YAML


Dlaczego tak:
  Dataclass łączy geometrię (FK, porty) z fizyką (promień, prędkość) w jednym
  obiekcie. Pole index mapuje na chromosom, routes_data przygotowuje
  wielotrasowe klocki (switche).


PORT
----
Lokalizacja: src/data.py:30-37

Pola:
  x: float                         pozycja X (studs)
  y: float                         pozycja Y (studs)
  heading: float                   kąt w stopniach
  gender: str                      "M" lub "F"

Dlaczego tak:
  Porty definiują gdzie klocki się łączą. Gender zapewnia kompatybilność
  połączeń (M+F). Frozen dataclass gwarantuje niezmienność po utworzeniu.


TRANSFORMACJA / FK (FKDeltas)
-----------------------------
Lokalizacja: src/data.py:17-27

Pola:
  dx: float                        przesunięcie X (studs)
  dy: float                        przesunięcie Y (studs)
  dtheta: float                    zmiana kąta (stopnie)

 Każdy klocek mówi: "jeśli wjedziesz do mnie, wyjedziesz przesunięty o (dx, dy) i obrócony o dtheta".

REPREZENTACJA GENU (element chromosomu)
---------------------------------------
Typ: numpy float64 (zaokrąglany do int32 podczas ewaluacji)

Znaczenie wartości:
  -1                               puste miejsce (slot nieużyty)
  0-9                              indeks klocka z katalogu (piece_index w YAML)

Gen nie jest obiektem ani strukturą. To pojedyncza liczba całkowita.

Dlaczego tak:
  pymoo wymaga numerycznych tablic. Integer encoding jest naturalny dla
  dyskretnego wyboru klocków. Wartość -1 pozwala na zmienną długość
  layoutu bez padding-obiektu.

CHROMOSOM (TrackLayoutProblem)
------------------------------
Lokalizacja: src/problem.py:26-67

Typ: np.ndarray(dtype=float64, shape=(n_piece_vars + 2,))

Struktura chromosomu:
  x[0:n_piece_vars]                indeksy klocków (-1 = puste, 0-9 = typ klocka)
  x[n_piece_vars]                  start_x (pozycja startowa X)
  x[n_piece_vars + 1]              start_y (pozycja startowa Y)

Parametry problemu:
  n_var = n_piece_vars + 2         długość chromosomu (klocki + pozycja)
  n_obj = 2                        cele: wykorzystanie, prędkość
  n_ieq_constr = 5                 ograniczenia: zamknięcie, kąt, granica, inwentarz, switche
  xl = [-1, ..., boundary.min]     dolne granice
  xu = [9, ..., boundary.max]      górne granice (max indeks = 9)


Chromosom to płaski wektor liczb zmiennoprzecinkowych (zaokrąglanych do int dla klocków).

Dlaczego tak:
  pymoo ElementwiseProblem wymaga płaskiej tablicy z granicami. Stała
  długość n_var umożliwia standardowe operatory genetyczne (crossover,
  mutacja). Repair naprawia nadmiar.


WEWNĘTRZNA STRUKTURA PO DEKODOWANIU (LayoutChromosome)
------------------------------------------------------
Lokalizacja: src/topology.py:177-240

Pola:
  loops: List[LoopDef]             lista pętli toru
  crossing_connections: Dict       połączenia skrzyżowań (Phase 4)

Dlaczego tak:
  Rozdziela genotyp (płaska tablica dla pymoo) od fenotypu (struktura
  topologii). Przygotowane na multi-loop layouty ze skrzyżowaniami
  w przyszłych fazach.
